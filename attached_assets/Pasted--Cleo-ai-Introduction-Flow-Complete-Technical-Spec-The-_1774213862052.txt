# Cleo.ai — Introduction Flow: Complete Technical Spec

## The Lifecycle

```
MATCH GENERATED → USER ACTIONS → DOUBLE OPT-IN → INTRO GENERATED
     → PREVIEW & APPROVE → EMAIL SENT → FOLLOW-UP → OUTCOME TRACKED
```

---

## STAGE 1: Match Generated (Automatic)

**Trigger:** User completes onboarding (profileComplete = true)
**When:** Immediately after onboarding, then nightly batch at 2 AM IST for new potential matches
**What happens:**
1. System generates profile embedding via OpenAI text-embedding-3-small
2. Runs cosine similarity against all other users (cross-persona: Founder↔Investor, Founder↔Talent)
3. Filters by: industry overlap, stage fit, location preference
4. Generates top 3-5 matches with score > 40%
5. For each match, calls OpenAI to generate a personalized "Why Connect" reasoning
6. Creates Match records with status = PENDING

**Emails/Notifications triggered:** NONE at this point. Matches are generated silently.

## STAGE 3: User Takes Action (Manual)

**Trigger:** User clicks Connect or Pass (via WhatsApp button, email link, or web UI)
**What happens:**

### If PASS:
- Update Match: user1Action or user2Action = "PASS"
- Update Match status = PASSED
- Create Activity: "You passed on Priya Sharma"
- **No email/notification sent to the other person.** They never know they were passed on.

### If CONNECT:
- Update Match: user1Action or user2Action = "CONNECT"
- Check if the OTHER user has also connected:
  - **If NO (one-sided so far):** Do nothing. Wait for the other user's action. Match remains PENDING.
  - **If YES (both connected = DOUBLE OPT-IN achieved):** → Proceed to Stage 4

## STAGE 5: Review & Approve (Manual)

**Trigger:** User clicks "Approve & Send" or "Edit"
**Who needs to approve:** EITHER user can approve. Only one approval needed — we don't need both to approve the intro text (that would create too much friction). The double opt-in was the connect step.

### If EDIT:
- User is taken to /introductions page where they can edit the intro text
- They can modify the text (their own part) and re-save
- Then click "Approve & Send"

### If APPROVE:
- Update Introduction status = APPROVED
- → Proceed immediately to Stage 6 (Send)

### Auto-approve timeout:
If neither user approves or edits within **48 hours**, auto-approve and send the intro. This prevents intros from going stale. Send a notification 24 hours in:

**24-hour reminder (WhatsApp):**
```
⏰ Your introduction to Priya is ready to send. 
I'll send it automatically tomorrow if you don't review it.

[Review Now →]  [Cancel Introduction]
```

## STAGE 8: Outcome Recorded (Automatic)

**Trigger:** User clicks a feedback button
**What happens:**

1. Update Introduction: outcome = selected option, status = COMPLETED
2. Create Activity: "You rated your intro with Priya as 'Great meeting'"

3. **Feed outcome into matching algorithm:**
   - GREAT_MEETING: +0.2 boost to similar matches (same industry, stage, location)
   - GOOD_CHAT: +0.1 boost
   - DIDNT_MEET: No change (neutral)
   - NOT_A_FIT: -0.1 penalty to similar matches + trigger analysis (why was this bad?)

4. **If GREAT_MEETING or GOOD_CHAT → Trigger vouch prompt (24 hours later):**

### Vouch request (WhatsApp):
```
🌟 Glad your conversation with Priya went well!

Would you like to vouch for her? A vouch helps other 
members trust her on the platform.

[Vouch for Priya ✓]  [Not now]
```

5. **If DIDNT_MEET → Send nudge to the other person (3 days later):**

### Nudge (WhatsApp to the person who didn't respond):
```
Hey Priya, Arjun mentioned you two haven't had a chance 
to connect yet. Here's a quick reminder:

Arjun Mehta — Co-Founder, NexaFlow (AI logistics)
Raising $2M seed | 📍 Bangalore

Would you still like to connect? I can help schedule a time.

[Schedule a call →]  [I'll reach out myself]  [Pass]
```

## EDGE CASES

### What if one user approves the intro and the other edits?
- Use the edited version. Last edit wins. If both edit, merge intelligently (keep each person's section).

### What if a user deletes their account after an intro is drafted but before sent?
- Cancel the introduction. Notify the other user: "This introduction has been cancelled."

### What if the email bounces?
- Log the bounce. Retry once after 1 hour. If still bouncing, notify the user via WhatsApp: "We couldn't deliver the introduction email to Priya. Please verify her email address."

### What if both users mark "Didn't meet"?
- Don't send a nudge to either. Log it as a missed connection. After 30 days, optionally resurface: "You were matched with Priya 30 days ago but didn't connect. Would you like to try again?"

### What if a user has WhatsApp off and email off?
- Always show notifications in the web app (activity feed + notification bell). Users can't turn off ALL notifications — web is always on.

### What if there are no matches for a user?
- Don't send empty notifications. Instead, after 7 days with no matches, send: "We're still looking for the right people for you. In the meantime, invite people from your network to improve your matches." (With invite codes)

### Rate limiting:
- Maximum 3 introductions sent per user per day (like Boardy's cap)
- Maximum 5 match notifications per day (don't overwhelm)
- Weekly digest replaces individual notifications if user has 5+ unreviewed matches

## TECHNICAL IMPLEMENTATION NOTES

### Sending emails via Resend:
You have Resend connected. Use it for ALL transactional emails.

```javascript
// Example: Send intro email via Resend API
const response = await fetch('https://api.resend.com/emails', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.RESEND_API_KEY}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    from: 'Cleo <intros@yourdomain.com>', // Must be verified domain on Resend
    to: [user1.email],
    cc: [user2.email],
    subject: `Introduction: ${user1.name} ↔ ${user2.name}`,
    html: introEmailHtml, // Use a nice HTML template
    reply_to: [user1.email, user2.email]
  })
});
```

### Scheduling follow-ups:
Use a cron job or delayed queue. Simple approach for Replit:

```javascript
// Daily cron at 10 AM IST (4:30 AM UTC)
// Check for introductions needing follow-up
const introsDueFollowUp = await prisma.introduction.findMany({
  where: {
    status: 'SENT',
    followUpAt: { lte: new Date() },
    outcome: null
  }
});

// Check for intros needing auto-approval
const introsNeedingAutoApproval = await prisma.introduction.findMany({
  where: {
    status: 'PENDING_APPROVAL',
    createdAt: { lte: new Date(Date.now() - 48 * 60 * 60 * 1000) }
  }
});
```

### The notification queue pattern:
Don't send notifications synchronously in API handlers. Use a simple queue:

```javascript
// When an event happens, queue the notification
await prisma.notificationQueue.create({
  data: {
    userId: user.id,
    type: 'MATCH_NOTIFICATION',
    channel: 'WHATSAPP', // or EMAIL or BOTH
    payload: { matchId, reasoning, matchName },
    scheduledFor: new Date(), // or future date for delayed sends
    status: 'PENDING'
  }
});

// Worker process (cron every 1 minute):
const pendingNotifications = await prisma.notificationQueue.findMany({
  where: { status: 'PENDING', scheduledFor: { lte: new Date() } }
});

for (const notif of pendingNotifications) {
  try {
    await sendNotification(notif); // Routes to WhatsApp or Email
    await prisma.notificationQueue.update({
      where: { id: notif.id },
      data: { status: 'SENT', sentAt: new Date() }
    });
  } catch (err) {
    await prisma.notificationQueue.update({
      where: { id: notif.id },
      data: { status: 'FAILED', error: err.message, retryCount: { increment: 1 } }
    });
  }
}
```

## STATE MACHINE DIAGRAM

```
Match Created (PENDING)
    │
    ├── User 1 clicks PASS ──→ Match PASSED (end)
    ├── User 2 clicks PASS ──→ Match PASSED (end)
    │
    ├── User 1 clicks CONNECT (waiting for User 2)
    │       │
    │       ├── User 2 clicks PASS ──→ Match PASSED (end)
    │       └── User 2 clicks CONNECT ──→ DOUBLE OPT-IN ✓
    │
    └── User 2 clicks CONNECT (waiting for User 1)
            │
            ├── User 1 clicks PASS ──→ Match PASSED (end)
            └── User 1 clicks CONNECT ──→ DOUBLE OPT-IN ✓

DOUBLE OPT-IN ✓
    │
    └── Match status = CONNECTED
        │
        └── Introduction created (PENDING_APPROVAL)
                │
                ├── User approves ──→ APPROVED ──→ Email sent (SENT)
                ├── User edits ──→ stays PENDING_APPROVAL
                ├── 24h reminder sent
                └── 48h auto-approve ──→ APPROVED ──→ Email sent (SENT)

Introduction SENT
    │
    └── 7 days later: Follow-up sent (FOLLOWED_UP)
            │
            ├── User: "Great meeting" ──→ COMPLETED ──→ Vouch prompt (24h)
            ├── User: "Good chat" ──→ COMPLETED ──→ Vouch prompt (24h)
            ├── User: "Didn't meet" ──→ COMPLETED ──→ Nudge other user (3d)
            └── User: "Not a fit" ──→ COMPLETED ──→ Matching penalty applied
```
