function getMatchablePersonas(userPersona) {

## BUG 5: Login Modal Drops Keyboard Characters (CRITICAL)

**Problem:** When users try to type in the login modal's email field, only the first character is captured. All subsequent keystrokes are silently dropped. Users literally cannot log in by typing.

**Fix:** This is likely caused by the modal re-rendering on each keystroke and losing focus, OR the cookie consent banner stealing focus. 

Check the login modal component. Common causes:

**Cause A: Uncontrolled re-renders.** If the input state is defined inside a component that re-renders the modal:

```jsx
// BAD — state in parent causes modal re-render
function Page() {
  const [showModal, setShowModal] = useState(false);
  const [email, setEmail] = useState(''); // This re-renders everything
  
  return <Modal><input value={email} onChange={e => setEmail(e.target.value)} /></Modal>;
}

// GOOD — isolate input state inside the modal component
function LoginModal() {
  const [email, setEmail] = useState('');
  return <input value={email} onChange={e => setEmail(e.target.value)} />;
}
```

**Cause B: Cookie banner z-index overlapping.** The cookie consent banner may have a transparent overlay that sits on top of the modal input, stealing click/key events.

```jsx
// Fix: When login modal is open, hide the cookie banner
{isLoginModalOpen && <div style={{ display: 'none' }}><CookieBanner /></div>}

// Or: Set modal z-index higher than cookie banner
<div className="fixed inset-0 z-[100]"> {/* Modal overlay */}
  <div className="z-[101]"> {/* Modal content */}
```

**Cause C: autoFocus or event handler conflict.** Add autoFocus to the email input and stopPropagation on the modal:

```jsx
<input
  type="email"
  autoFocus
  value={email}
  onChange={e => setEmail(e.target.value)}
  onClick={e => e.stopPropagation()}
  onKeyDown={e => e.stopPropagation()}
/>
```

**Test after fixing:** Type a full email address and verify ALL characters appear.
